# Resolving Failed Email Sending in Automation Scenarios with Make.com and Microsoft 365 Email
## Overview
The integration of Make.com with Microsoft 365 Email (Outlook) is a common automation scenario for businesses to streamline their workflows. However, users often encounter issues with sending emails due to authentication problems. This Standard Operating Procedure (SOP) aims to provide a comprehensive guide to resolving the "Failed to send email in automation scenario" error when using Make.com and Microsoft 365 Email.

## Error Diagnostic
The core error "Failed to send email in automation scenario" is typically caused by missing or incorrect authentication credentials for the Microsoft 365 Email (Outlook) integration. This can occur due to various reasons such as:
- Incorrect username or password
- Insufficient permissions
- Expired or invalid authentication tokens
- Misconfigured API connections

## Step-by-Step Resolution
### Step 1: Verify Microsoft 365 Email Credentials
Ensure that the username and password used for the Microsoft 365 Email integration are correct and have the necessary permissions to send emails.

### Step 2: Configure Microsoft 365 Email API Connection
Set up a new API connection in Make.com using the correct Microsoft 365 Email credentials and permissions. This may involve creating a new Azure AD application and granting the necessary permissions.

### Step 3: Update Make.com Module with New API Connection
Update the Make.com module with the new API connection and verify that the authentication credentials are correct.

### Step 4: Test the Automation Scenario
Test the automation scenario to ensure that the email is sent successfully. If the issue persists, verify the API connection and authentication credentials.

### Step 5: Verify Email Sending
Verify that the email is sent successfully by checking the email inbox and the Make.com module logs.
